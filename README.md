# 文章工作台 · Web 2.1

[在线使用](https://shimt9105-eng.github.io/article-workbench/)

打开网页直接体验，无需注册或登录。横向三步 Tab：找对标 → 开始创作 → 提意见；创作页保留编辑2号的任务列表、文章预览、System 和模型版本布局。

## 体验额度

整个网站所有访客合计10次体验调用，用完不按天重置，换浏览器或清除缓存也不会补发。后端使用原子计数限制并发，前端显示剩余额度。

搜索、AI 推荐、每个模型生成或修改、每张封面分别计1次，失败调用也计入。保存正文、查看文章和验证公众号绑定不计次。额度用完仍可查看已有文章。共享或用户自用 API 配置均受同一总额限制。

## 历史文章

保留两条历史任务、11个模型版本，其中9个有正文、2个为原始失败版本。3张原图去重保存，6处正文图片引用保留。公开副本只包含历史成稿、时间、模型和成功/失败状态；原始资料、随笔、私人修改记录、电脑路径及凭据未公开。桌面原始状态未修改。

历史副本只读，可切换模型查看，不能修改或发送。新文章存入当前浏览器的访客空间，与其他访客隔离。

从项目根目录更新历史副本：

```sh
node outputs/文章工作台GitHub网页版/script/history-export.mjs <历史state.json路径> outputs/文章工作台GitHub网页版/script/web/history.json
```

脚本校验原状态未变，复制图片并记录校验值。确认成稿可公开后再提交，不提交原始状态文件。

## 使用流程

1. 找对标：填写主题和方向，明确选择来源 / 模型；AI 推荐3篇真实搜索结果，不足3篇按实际数量显示。选入后读取全文，无法读取时粘贴完整正文。
2. 开始创作：选择写作模型，上传 `.docx` 或粘贴资料，提供对标全文与原始随笔。复用编辑2号固定 System、生成 core 和配图逻辑，保留多模型独立版本。
3. 提意见：选中文字或填写修改意见，按同一依据更新全文。正文可直接编辑保存，过期版本拒绝覆盖。
4. 绑定公众号：使用自己的 AppID + AppSecret，检查接口权限及服务器出口 IP 白名单，不需要公众号登录密码。
5. 发送草稿：生成封面、上传图片并保存到公众号草稿箱，再到微信后台检查与正式发布。工作台不会自动正式发布。

网页不能读取电脑路径。`.doc` 须转为 `.docx`；私有资料需要粘贴或上传 Word。对标摘要不能代替全文。

## 数据保存

随机访客凭据保存在浏览器 localStorage，刷新可继续使用。清除网站数据或换浏览器后无法找回原访客空间；请在自己的可信浏览器绑定公众号。服务器验证签名并隔离访客任务，公众号和自用 API 凭据用 AES-256-GCM 加密保存。

每个模型版本拥有 revision 和 attempt ID，旧结果不能覆盖新版本，失败保留已有正文。发送按访客、任务、模型、公众号和正文哈希去重。微信结果不确定时禁止自动重发，应先检查草稿箱。

## 部署与维护

`web/` 是 GitHub Pages 网页、公开历史成稿和原图；`backend/` 是 CloudBase HTTP 云函数，使用独立的 `article_web_*` 集合。`tests/` 使用隔离数据和模拟调用。main 推送后自动运行测试并发布网页。

从项目根目录部署：

```sh
python3 outputs/文章工作台GitHub网页版/script/deploy.py
```

需要已授权的 DWS、CloudBase CLI 和文章机器人配置。换电脑须重新安装工具并登录。加密和签名密钥保存在 `$HOME/.config/article-workbench-web/backend-secrets.json`，权限600；后续部署须复用，不放入仓库或 outputs。部署不重置10次额度，也不改写桌面状态。

本地隔离验证：

```sh
cd outputs/文章工作台GitHub网页版/script
npm ci --prefix backend
npm test
QA_PORT=4383 node tests/qa-server.js
```
